# Перенос наработок в DDH

DDH хранит итоговую поставку и её проверки. Разработку отдельного навыка, инструмента или интеграции можно вести в своём репозитории. Когда изменение готово, его можно перенести в DDH с привязкой к проверенной версии источника.

1. Опишите, какую задачу решает изменение. Зафиксируйте коммит, нужные файлы, права распространения и наблюдаемый результат.
2. Найдите точку в DDH, которой принадлежит решение. Уточнение ведёт DDH, состояние проекта ведёт CPT, предметную методику держит соответствующий экспертный пакет. Если метод уже есть, обновите его и проверьте прежние сценарии.
3. Выберите форму переноса. Практика может стать частью существующего навыка. Внешний исполнитель оформляется как подключаемая интеграция. Публичную реализацию включайте в поставку, когда понятны права, зависимости и способ обновления. Для частного источника публикуйте только согласованную переработку.
4. Запишите в `sources.json` назначение, условия использования и проверенную ревизию. Для вложенной поставки укажите путь и коммит. При изменении версии источника обновите запись в том же PR.
5. Добавьте проверку, которая показывает результат в DDH. Для навыка проверьте момент вызова и пересечение с существующими правилами. Для кода проверьте нормальный вход, установку и обновление. Для адаптера зафиксируйте, что проверено на каждом хосте.

Практика аудита решений из отдельного репозитория уже используется в `ddh-decision-audit`. Figma Console остаётся отдельно подключаемым исполнителем, а её проверенная версия зафиксирована в реестре.
