# План интеграции DDH и Product OS

DDH развивается из Product OS 4.1. Полная поставка включает CPT runtime, основные навыки DDH, выборочные экспертные пакеты, средства проверки и единый путь установки. Исходная точка CPT закреплена на теге v4.1.0 и коммите `1870f6fc200638a200348762004d24c2803f93b1`. [Исходный релиз 4.1](https://github.com/Lofiette/design-director-harness/tree/v4.1.0)

## Что сохраняем и что меняем

| Область | Решение | Проверка |
|---|---|---|
| Runtime и данные проекта | Сохраняем формат `.cpt`, допуски, задачи, Product Knowledge, YAML-чекпоинты, проверку их целостности и восстановление. | Активная задача, допуск и чекпоинт 4.1 читаются после установки и обновления. Байты существующего `.cpt` совпадают. |
| Маршрутизация | `ddh-direct` ведёт уточнение запроса. CPT ведёт состояние, планирование и допуск в проекте. Данные уточнения используются повторно. | Микроправка, существенный вопрос без зависимых записей, частичный ответ, стандартная задача и возобновление. Поведение модели проверяется отдельно. |
| Экспертиза | Сохраняем пять пакетов CPT. Пользователь выбирает пакеты, агент читает метод под конкретный пробел. Объёмные процедуры выносим в справки навыка. | Нативный каталог Codex и провайдер DSH загружают выбранные навыки. Проверяются лимиты, ссылки и конфликт владения файлами. |
| Установка и восстановление | DDH и новый CPT ставятся одной транзакцией. Существующий валидный CPT 4.1 используется как есть. Выбор пакетов сохраняется при обновлении. | Чистый проект, активный 4.1, старый DDH, повтор, конфликт, остановка посреди записи и восстановление. |
| Хуки и воркеры | Сохраняем реализации CPT. Исправляем привязку персонального receipt к профилю Codex. Проверяем нативные хуки по хостам и документируем проверенный режим CLI. | Профили с отдельными receipts, тесты событий и ручной проверки снимка. Отдельно проверить запуск и доверие хуков в Codex, затем поддержку событий в DSH. |
| Источники | Сохраняем происхождение и добавляем практику после проверки триггера, результата, условий распространения и пересечений. | Новая практика даёт отдельное решение или артефакт. У неё есть наблюдаемый сценарий и проверка конфликта с имеющимся методом. |

## Сверка практик

Проверено 28 собственных репозиториев по веткам по умолчанию, включая один без доступной основной ветки. Прочитан 121 закреплённый входной файл, из них 96 файлов навыков. Отдельно сверены 15 GitHub Stars и списки рекомендаций и установки DSH. В этих списках найдено 28 уникальных ссылок GitHub после нормализации, из них 20 отсутствуют в реестре опубликованного DDH. Это очередь кандидатов для отбора по назначению и проверкам. Спектр исключён.

79 исторических идентификаторов навыков уже сопоставлены с каноническими методами в `product-os/migration/SKILL_MIGRATION.csv`. Для них используем существующие реализации и отдельно проверяем уникальные отличия. Узкоспециализированные проектные практики проверяем на отдельный пакет или адаптер. Общие инварианты проверки, восстановления и обращения с артефактами рассматриваем для основного маршрута. Реестр приватных источников и закреплённых файлов хранится локально.

## Установка DDH

Из корня рабочей копии DDH с Node.js 22+, Python 3.10+ и зависимостями из `product-os/requirements.txt`:

```powershell
node tools/ddh.mjs install --project "C:/path/to/project" --packs cpt-design-ui
node tools/ddh.mjs update --project "C:/path/to/project"
```

Если установлен `uv`, он может подготовить изолированную среду одной командой.

```powershell
uv run --no-project --with-requirements product-os/requirements.txt node tools/ddh.mjs install --project "C:/path/to/project" --packs cpt-design-ui
```

Параметр `--python` задаёт путь к подготовленному Python. Параметр `--packs` принимает список через запятую. При обновлении без него используется предыдущий выбор. Доступны `cpt-design-ui`, `cpt-product-research`, `cpt-engineering`, `cpt-risk-operations` и `cpt-ai-agentic`.

При первой установке локальное состояние CPT добавляется в игнорирование Git, а существующие инструкции проекта сохраняются. Обычный `update` также подхватывает установленную Product OS 4.1. Для этого нужны рабочий runtime, receipt и один активный CPT-блок в `AGENTS.md`. Подключённые пакеты записываются в receipt DDH. Для восстановления прерванной установки используется `repair-install`. Для нативных плагинов и средств миграции доступны исходные инструменты в `product-os/`.

## Проверено в локальном кандидате

- Чистый Product OS 4.1 прошёл полный офлайн-набор из 201 сценария, а также штатные проверки, сравнение с базой и проверки мутаций.
- Новый установщик сохраняет существующий CPT, его допуск и чекпоинт. При переходе с опубликованных 4.1 и DDH 5.0.0 все 13 файлов CPT в тестовом проекте совпали побайтно.
- Нативный Codex App Server обнаружил 51 навык. Установленный провайдер DSH загрузил те же 51 навыков.
- В новый CPT добавлена установка руководства операций. Receipt персонального пакета воркеров определяется по профилю Codex с сохранением чтения совместимого старого receipt.

## Условия раскатки

1. Завершить офлайн-проверку чистого тега 4.1 и отдельно выполнить регресс изменённого кода. Хранить результаты конкретных коммитов раздельно.
2. Проверить рабочие сценарии с CPT и DDH вместе. Включить открытый вопрос, возобновление, выбор эксперта, обновление и откат. Сравнивать время, служебные действия и точность результата по каждому сценарию.
3. Подготовить скачиваемую полную сборку с проверкой и простой подготовкой Python в изолированной среде. Проверить установку из скачанного архива, повтор, обновление, удаления опциональных пакетов и восстановление после сбоя.
4. Выпустить кандидат после проверки каталогов, запуска, обновления и восстановления на заявленных платформах. Живые проверки опроса, хуков и Figma Console имеют отдельные сценарии и критерии допуска.
