# Переносимое окружение DDH

Статус: проект контракта, 2026-11-21. Совместим с существующим устройством DDH 5.0.1. Этот документ не добавляет новый runtime, автоматически подключённые хосты или фоновую синхронизацию.

## Три слоя и владение данными

| Слой | Каноническое содержимое | Не хранить как второй источник истины |
|---|---|---|
| Контекст владельца и проектов | Проверяемые факты, история изменений, источники, результаты применения методов, фактические измерения, разрешённые к публикации кейсы | Общие версии методик и личность помощника |
| DDH | Методы, навыки, схемы, формулы, валидаторы, шаблоны, адаптеры и критерии проверки | Приватный профиль, фактические показатели конкретной организации и её результаты |
| Конструкт помощника | Имя и голос, принципы решений, история собственного опыта и пересмотра решений, правила памяти | Полная копия пользовательского профиля или всех DDH навыков |

У каждой записи есть один канонический владелец. Остальные слои ссылаются на стабильный идентификатор, версию и источник. Сгенерированный отчёт или поисковый индекс является производным представлением и не меняет исходные факты самостоятельно.

DIS или другой измерительный инструмент относится к DDH: определения показателей, расчёт, ограничения интерпретации, требования к данным. Применение инструмента — выбранный периметр, периоды, первичные наблюдения, фактические значения и выводы — относится к контексту проекта. Результат фиксирует версию инструмента и ревизию входов. Шаблон с пустыми значениями не является измерением.

## Композиция без копирования всей памяти

[environment.lock.example.json](../contracts/environment.lock.example.json) показывает состав окружения. Это незаполненный пример, не валидная установленная конфигурация: `example_only: true`, `null` и отсутствующие доказательства должны сохранять состояние `not_ready`.

Для рабочего lock нужны неизменяемые ревизии или digest каждого источника. `main`, `latest` и абсолютный путь сами по себе не идентифицируют содержимое. Локальный путь может помогать разрешению, но не заменяет ревизию. Секреты, токены, полные журналы сессии и закрытые данные в публичный DDH не включаются. Пользовательская композиция хранится в принадлежащем ей приватном контуре.

При начале задачи достаточно:

1. Короткого ядра конструкта помощника и карты источников.
2. Текущего запроса и релевантных ограничений владельца/проекта.
3. Выбранного метода DDH и только требуемых им справок.
4. Ссылки на активную задачу и проверенные артефакты, если работа продолжается.

Исторические записи, большие логи, весь каталог методов и полный профиль не загружаются телом при каждом старте. Поиск возвращает ограниченные фрагменты с source ID, датой, ревизией и статусом актуальности; при спорном выводе агент открывает первоисточник. Исправление факта создаёт новую текущую запись и связь с предыдущей, а не стирает историю.

## Согласование с существующим DDH

- `manifest.json` описывает поставку, а `.agents/ddh-install.json` — установленную версию и управляемые файлы. Новый composition lock не заменяет эти receipts.
- `tools/ddh.mjs doctor` в 5.0.1 проверяет содержимое сборки и выводит объявленные возможности. Это **статическая проверка пакета**, а не подтверждение возможностей активной сессии.
- `test/dsh-provider-smoke.mjs` проверяет нативный DSH loader отдельно от работы модели. Обнаруженный навык ещё должен пройти поведенческий сценарий.
- Активную задачу, lease и YAML checkpoint ведёт CPT в `.cpt/`. DDH JSON handoff дополняет её ссылками и контрольными суммами, не создавая конкурирующую задачу.
- [adapters/AGENTS.ddh.md](../adapters/AGENTS.ddh.md) остаётся короткой точкой входа. Метод не должен переопределять актуальные инструкции пользователя или разрешения хоста; при расхождении требуется явно назвать ограничение и его источник.

## Контракт возможностей хоста

[host-capability-report.example.json](../contracts/host-capability-report.example.json) разделяет пять уровней:

| Проверка | Подтверждает | Не подтверждает |
|---|---|---|
| `static_bundle_validation` | Проверены файлы поставки, manifest, ссылки и ограничения упаковки | Активная сессия видит эти файлы |
| `installation_validation` | Проверены установленные файлы и receipts проекта | Нативный каталог выбрал именно их |
| `provider_discovery` | Активный provider обнаружил нужные имена и происхождение | Модель применяет инструкции |
| `live_workflow` | Указанный сценарий выполнен в записанной конфигурации | Все задачи и другие версии работают так же |
| `user_acceptance` | Результат принят по заданным критериям | Универсальная гарантия качества |

Разрешённые статусы: `not_run`, `pass`, `fail`, `blocked`, `unknown`. `blocked` означает, что проверка не состоялась по названной причине; его нельзя считать ни успешным, ни проваленным поведением модели. Отсутствующие usage/cost данные сохраняются как `null`.

Доступность операции описывается отдельно: `available`, `unavailable`, `unknown`. Для наблюдения нужны probe, время и evidence. Capability не равна авторизации: доступный инструмент может быть запрещён для конкретной задачи. Native permission state и уже данное пользователем разрешение должны учитываться без повторного запроса по умолчанию. Если обязательная операция отсутствует, выполняется независимая доступная часть, а зависимая помечается `blocked`.

Контракт может требовать filesystem read/write, process execution, Git, network, skill loading, browser interaction, independent reviewer, пользовательский ответ, durable checkpoint или MCP. Не все задачи требуют все возможности. Названия native tools сопоставляются адаптером; нейтральный метод не предполагает, что `exec`, `Bash` или `Shell` существуют во всех хостах.

## Адаптеры

DDH 5.0.1 декларирует `codex` и `dsh`. Новые хосты добавляются только с наблюдаемым набором проверок. Совпадение `.agents/skills` уменьшает объём адаптера, но не подтверждает одинаковые порядок инструкций, approvals, hooks, запуск subprocess и resume.

Kimi Code — кандидат отдельного адаптера. Внешний источник для проверки: [официальная документация skills](https://moonshotai.github.io/kimi-code/en/customization/skills). Старый `MoonshotAI/kimi-cli` архивирован; актуальный [kimi-code](https://github.com/MoonshotAI/kimi-code) имеет собственные agents, plugins и lifecycle. До live-проверки он не должен появляться в `manifest.hosts` как подтверждённый.

Среда чата без shell — отдельный режим: методы могут выполняться через доступные connectors, удалённый сервис или подготовленный пакет. Нельзя приписывать ей возможности CLI по названию модели. MCP переносит контракт инструментов/ресурсов; он не обеспечивает сам по себе синхронизацию личности, выбор контекста или одинаковое поведение моделей.

## Следующий ограниченный шаг реализации

Добавить наблюдения среды к существующей диагностике, сохранив прежний вывод doctor для совместимости. Поле проверки пакета должно называться явно; общий `runtime_verified: true` недопустим без ссылки на завершённый live-сценарий для конкретной версии хоста и модели. Реализация этого изменения остаётся отдельной задачей. В этом пакете предложены только документы, примеры и [протокол проверки](../evaluation/PORTABILITY.md).

## Первичные основания

- [Agent Skills specification](https://agentskills.io/specification): metadata, инструкции и ресурсы раскрываются по необходимости.
- [AGENTS.md](https://agents.md/): единая точка навигации для агентов.
- [MCP architecture](https://modelcontextprotocol.io/docs/learn/architecture): протокол обмена контекстом и инструментами не определяет управление контекстом самого приложения.
- [Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents): небольшой релевантный контекст, ссылки и внешние записи состояния.
- [Harness design for long-running applications](https://www.anthropic.com/research/harness-design-long-running-apps): проверяемые критерии, независимая оценка сложной работы и проверка необходимости каждого элемента harness.

Это архитектурные рекомендации по опубликованным практикам и наблюдениям кода DDH. Результат на другом host или модели требует собственного испытания.
