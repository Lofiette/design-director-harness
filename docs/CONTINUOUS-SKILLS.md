# Непрерывное развитие навыков

Статус: переносимая процедура и границы исполнения. `continuous-memory` v0.1 реализует только анализ явно переданных событий и fingerprints; авторинг, native installation и live evaluation выполняются отдельным агентом/адаптером. Этот документ сам их не активирует.

## Канонический владелец и область действия

Различать владельца сведений (`profile`), метода (`toolkit`) и устойчивых принципов помощника (`identity`). Одна процедура имеет одну каноническую версию. Свидетельства её появления могут оставаться в закрытом контуре, а в общий toolkit переносится только обобщённый метод. Сохранить private provenance отдельно; не копировать исходные данные в общие примеры.

Различать реестр известных процедур, каталог файлов поставки, фактически обнаруженные host-provider skills и реально применённый навык. Пустой декларативный реестр — не результат сканирования хоста. Если provider discovery отсутствует, `active_catalog_coverage` остаётся `unknown` в отдельном observation-документе. Не добавлять неподдерживаемые поля в registry v0.1.

## Выделение процедуры

1. Зафиксировать действительную задачу, исходную revision, стабильный `run_id`, результат и приёмку. Не считать повторный импорт новым выполнением.
2. Сопоставить повторяемые сценарии через явный `workflow.key` и различия контекстов. CLI v0.1 не осуществляет семантическое объединение необработанных разговоров.
3. Проверить существующие навыки по доступным источникам. Сохранить неполноту покрытия; отсутствие найденного дубля не доказывает отсутствие дублей вообще.
4. При выполнении принятого порога создать кандидат со ссылками на доказательства. Стартовая настройка v0.1 — три успешных независимых запуска в двух контекстах; это эвристика, доступная настройке.
5. Сформировать `SKILL.md`, минимальные необходимые resources, realistic eval cases и декларацию scope. Автоматический авторинг использует только подтверждённую процедуру и обозначает предположения; не сочиняет историю успехов.

Авторизованное пользователем автоматическое создание драфтов не требует повторного разрешения на каждое создание. Драфты хранить в явно неактивном каталоге `skill-candidates/` вне каталогов, которые хост автоматически загружает. Наименование стабильное, изменения ревизионные. Пути окончательного подключения определяет host-adapter, а не универсальная инструкция.

## Пакет кандидата

| Файл | Содержание |
|---|---|
| `SKILL.md` | Name, description с triggers, workflow, входы, выходы, проверки, границы |
| `candidate.json` | Owner, workflow key, status, version, proposed scope, зависимости и related skill IDs |
| `evidence.json` | Ссылки на реальные задачи/запуски/приёмку и source revisions; может оставаться приватным |
| `evals/cases.json` | Сценарии успеха, негативные triggers, ошибки/неполные данные, приёмка |
| `evaluation.json` | Фактические результаты по конфигурациям; `not_run` и `blocked` отдельно от fail |

В активный контекст не переносить весь evidence-пакет. Достаточны metadata, необходимые инструкции и адресуемые справки. Итоговый skill version связывается с проверенной source revision, а результат использования — с этой версией.

## Проверка эффективности

Статический валидатор подтверждает форму файла, native discovery — обнаружение, live workflow — поведение. Эти результаты не взаимозаменяемы.

Сравнить одинаковые задачи и входы в одной наблюдаемой конфигурации с навыком и без. Использовать отложенные сценарии, не показанные при создании инструкций. Если требуется оценить переносимость, повторить для каждого заявленного host/model scope. Учитывать отдельными показателями качество, критические ошибки, ручные исправления, ложную активацию, latency и наблюдаемые затраты. Не заменять неизвестные значения нулями.

Автоматическая активация вновь созданного навыка допускается только в пределах уже предоставленных пользователем полномочий и фактически испытанного scope. Положительный результат на одном host/model не даёт глобального PASS. Если native installation недоступен или поведенческая проверка не состоялась, драфт сохраняется с причиной, а не получает выдуманный active status. Реальный permission blocker называется явно; локальная процедура не создаёт лишний запрос согласования.

## Смена модели, хоста или инструмента

На старте и при доступном событии обновления адаптер собирает fingerprint согласно [HOST-CONTINUITY-ADAPTER.md](HOST-CONTINUITY-ADAPTER.md). Неизвестные поля остаются `null`. Наблюдаемое изменение конфигурации запускает оценку применимых активных навыков; вывод не обязан распространяться на неиспользуемые области.

Различать знания проекта/прав/источников, обязательную методику и процедурную поддержку модели. Более сильная модель может уменьшить потребность в последней, сохраняя первые две категории. Это проверяемая гипотеза по каждой процедуре, а не автоматическая причина удаления.

После сравнительного прогона сформировать предложения `add`, `change`, `merge`, `retire`, `keep` или `insufficient_evidence` с конкретным diff/основанием, affected scope, доказательствами и планом проверки. В v0.1 CLI выдаёт `revalidate`, а не такие содержательные выводы: их формирует последующий агент по результатам.

Если пользователь запросил предложения по обновлению существующих навыков, не превращать их в самовольное применение и удаление. Никогда не удалять историю. Состояние retired означает снятие из выбранного активного scope с сохранённой предыдущей revision и способом возврата. Не менять skills, которыми пользователь не владеет, лишь потому что они найдены в каталоге.

## Наблюдение и ограничение разрастания

Число созданных навыков не является KPI качества. Полезные критерии: доля подтверждённых повторяемых workflow, качество на отложенных задачах, ложные срабатывания, длина загружаемых инструкций, цена поддержания, число обязательных ручных правок и дрейф после обновления среды.

Не создавать новую процедуру для каждого диалога. Повторяющееся разъяснение может стать короткой справкой, шаблоном или поправкой существующего навыка. Объединение оправдано, если сохраняет точные triggers и не заставляет загружать нерелевантный контекст. Слабые/непроверенные кандидаты остаются неактивными.

## Основания

- [Agent Skills specification](https://agentskills.io/specification) и [evaluation guide](https://agentskills.io/skill-creation/evaluating-skills): формат и проверка результатов.
- [SkillsBench v4](https://arxiv.org/abs/2602.12670v4): парное сравнение и зависимость эффекта от model-harness configuration; это не измерение нашего экземпляра.
- [NVIDIA SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator): раздельные проверки структуры, overlap и фактического поведения; внешний кандидат для дальнейшего CI, не установленный этим документом.
