# Design acceptance matrix

| Dimension | Evidence |
|---|---|
| Task outcome | Primary path exercised from its intended entry point with realistic data |
| State coverage | Normal, empty, loading, error, permission and success states reviewed where relevant |
| Recovery | Retry or correction preserves the right data, focus and status |
| System | Existing tokens and components identified, with exceptions explained |
| Layout | Evidence at representative widths and for long or localized content |
| Accessibility | Keyboard, focus, names, announcements, contrast and motion checked where applicable |
| Handoff | Component and state contracts, source links, evidence, gaps and explicit status |

Capture evidence from the intended surface. Record unavailable states as unverified. Treat a screenshot as evidence for its captured size and state.
