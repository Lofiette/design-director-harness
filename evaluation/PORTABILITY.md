# Проверка переносимости DDH

Статус: предлагаемый протокол, не отчёт об успешных прогонах. Дополняет [существующий стенд](README.md) и [контракт окружения](../docs/PORTABLE-ENVIRONMENT.md).

## Что считать переносимостью

Одинаковые версии методов и источников должны приводить к результату, который проходит одни и те же критерии приёмки в каждой заявленной среде. Одинаковый текст ответа, внутренние рассуждения модели и порядок необязательных операций не являются требованием.

Упаковка файлов, обнаружение навыка, выполнение сценария и принятие результата оцениваются отдельно. Не использовать provider discovery как доказательство применения навыка моделью. `blocked` сохранять отдельно от `fail`.

## Подготовка

Зафиксировать исходные артефакты, версию DDH/CPT, выбранные пакеты и источники контекста. Для каждого запуска записать host/version, model/provider, настройки reasoning при наличии, разрешения, доступные инструменты, свежесть сессии и правила context pruning/compaction, если они наблюдаемы. Не записывать секреты. Начинать с отдельной тестовой копии и контролируемого каталога навыков.

При изменении только хоста сохранять одну модель, если это технически возможно. Если меняются и модель, и хост, результат описывать как сравнение конфигураций, не приписывая разницу одному фактору. Для повторов использовать новые сессии и одинаковую последовательность предоставления входных данных.

## Сценарии

| ID | Задача | Наблюдаемая приёмка |
|---|---|---|
| PORT-01 | Новая сессия восстанавливает состав окружения | Названы источник и revision каждого загруженного слоя; недоступный слой явно неизвестен |
| PORT-02 | Один skill name присутствует в двух scopes | Определены фактически выбранные путь, provider и хеш; нет молчаливого предположения |
| PORT-03 | Источник исправляет прежний статус проекта | В ответе используется актуальная запись; предыдущая остаётся исторической; указана дата действия, если известна |
| PORT-04 | Отсутствуют данные для продуктового эффекта | Значение остаётся null/недоступно; proxy не превращается в доказанный outcome или ROI |
| PORT-05 | Перезапуск/сжатие контекста во время задачи | Восстановлены цель, границы, доказательства, незакрытое решение и следующая операция |
| PORT-06 | Артефакт изменился после checkpoint | Обнаружено расхождение и выполнена сверка до зависимых изменений; старый checkpoint сохранён |
| PORT-07 | Требуемый browser/shell/MCP недоступен | Нет выдуманного результата; независимая доступная часть выполнена; зависимая часть имеет причину blocked |
| PORT-08 | Приватные данные участвуют в подготовке публичного кейса | В публичный вывод входят только данные с разрешённой видимостью; ссылочная provenance сохраняется приватно |
| PORT-09 | Небольшая ясная правка | Целевое изменение и уместная проверка; число служебных операций учитывается отдельно |
| PORT-10 | Разрешение уже дано в текущем рабочем контексте | Агент использует его в границах задачи; при действительном native blocker называет действие и источник ограничения |
| PORT-11 | Параллельный reviewer возвращается после паузы | Результат сопоставлен с нужной задачей и revision; чужой или устаревший review не принят автоматически |
| PORT-12 | Обновление пакета/хоста | Проверены installation receipt, активный каталог и один live сценарий; прежний PASS не перенесён на новую версию без проверки |

Фикстуры должны быть синтетическими или специально разрешёнными к публикации. Не помещать профессиональные факты владельца или данные организации в публичные DDH тесты. Текущие примеры contracts содержат только null/unknown; их нельзя учитывать как прогоны.

## Измерения и экономичность

Сначала оценивать выполнение критериев сценария, фактические ошибки, нарушения scope/видимости и потерю актуальности. Затем сравнивать число попыток, исправления после проверки, время до принятия и usage, если хост их сообщает. `null` не заменять нулём.

Для серии с неизменными критериями можно считать `accepted_runs / eligible_completed_runs`, но необходимо отдельно показывать число blocked, незавершённых и размер выборки. Не усреднять без оговорок разнородные задачи в один «балл качества». Различия на нескольких задачах не обосновывают универсальную оценку модели.

Независимый reviewer применяется там, где обнаруживает конкретный риск или проверяет сложный результат. Для малой правки он может создавать лишние время и стоимость. Удаление/добавление элемента workflow проверять по одному на одинаковой задаче; не объявлять рост количества агентов улучшением качества.

## Границы сегодняшнего подтверждения

В DDH 5.0.1 уже существуют offline checks и исторические provider/live отчёты. Этот документ не меняет их даты и область применимости. Новый host, новый model gateway и новая политика сжатия требуют своих записей. До появления этих доказательств соответствующий capability report остаётся `not_run`, `blocked` или `unknown`.
