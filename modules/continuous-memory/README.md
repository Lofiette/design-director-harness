# Continuous Memory — DDH experimental module

Версия `0.1.0`. Исполняемый локальный модуль на Python 3.10+ и стандартной библиотеке. Он сохраняет переданные исходники, проверяет связность памяти, строит навигацию по уровням, выбирает материал для дневного обзора и формирует предложения по навыкам. Он не подключён к DDH installer/ZIP, не перехватывает автоматически историю агентских сред и не публикует контент.

## Владение

Экземпляр задаёт соответствие трёх нейтральных владельцев своим репозиториям:

| Owner | Каноническое содержание |
|---|---|
| `profile` | Факты владельца, проекты, наблюдения, результаты и измерения |
| `toolkit` | Повторно применимые методы и процедуры |
| `identity` | Устойчивые принципы помощника, его решения и история их пересмотра |

Код, схемы, тесты и общие правила находятся в DDH. Фактические события, сырые записи и найденные по ним кандидаты навыков сохраняются в экземпляре памяти соответствующего владельца. Видимость кандидата наследует наиболее закрытую видимость его доказательств: назначение `toolkit` не делает частные сведения публичными.

## Что сохраняется и что сжимается

`source → episode → day → project → overview` — уровни доступности сведений, а не последовательное уничтожение подробностей.

- `objects/<sha256>` содержит точные переданные байты. Повторное содержание не дублируется.
- `events/<sha256(event_id)>.json` содержит читаемую запись и контрольную сумму её канонического JSON.
- Обзор ссылается на события более низкого уровня через `sources`.
- `lookup` возвращает сначала наиболее высокий совпавший уровень. `get` открывает выбранную полную запись; ссылки ведут к событиям и исходным объектам.
- `index` — восстанавливаемая проекция. Ни индекс, ни статья, ни обзор не заменяют первичные записи.
- Исправление создаёт событие `correction` с `fact_key` и `supersedes`. Предыдущие байты сохраняются. Две несовместимые неснятые записи становятся явным конфликтом, а не победой самой поздней даты.
- Обобщение не может молча стать наблюдаемым фактом: `summary` не владеет `fact_key` и не допускается как первичное свидетельство для нового эпизода/факта.

`captured_at` означает момент поступления записи. `occurred_at` означает время события и может быть неизвестно. `valid_from`/`valid_to` — отдельный полуоткрытый интервал действия утверждения; этот прототип не реализует полный темпоральный запрос «что было истинно на дату». Метка `current_record` означает отсутствие явного преемника, а не доказанную истинность.

## Команды

Команды выполняются из корня DDH. `instance` — приватный или разрешённый локальный каталог конкретного окружения. Не помещать рабочие данные в публичный каталог этого модуля.

```bash
python3 modules/continuous-memory/ddh_memory.py ingest --store instance/memory --event event.json --raw source.txt
python3 modules/continuous-memory/ddh_memory.py verify --store instance/memory
python3 modules/continuous-memory/ddh_memory.py lookup --store instance/memory --query 'нужная тема' --limit 8
python3 modules/continuous-memory/ddh_memory.py get --store instance/memory --event-id stable-event-id
python3 modules/continuous-memory/ddh_memory.py index --store instance/memory
python3 modules/continuous-memory/ddh_memory.py daily --store instance/memory --date 2030-01-02 --timezone Europe/Moscow
python3 modules/continuous-memory/ddh_memory.py skill-candidates --store instance/memory --registry instance/skill-registry.json
python3 modules/continuous-memory/ddh_memory.py model-scan --previous previous.json --current current.json --registry instance/skill-registry.json
```

Дата в примере синтетическая; команда требует фактическую целевую дату. Пустой реестр есть в `contracts/empty-skill-registry.json`. Это отсутствие зарегистрированных навыков, не результат сканирования пользовательской среды.

Вывод — JSON в stdout. Обновляемую проекцию можно сохранять вызывающим процессом отдельно. Ошибка возвращает код 2 и JSON в stderr. Отчёты не записываются как реальные факты автоматически. `get`, `lookup`, `index` и анализ сначала проверяют целостность архива.

## Формат записи

Схема: `contracts/memory-event.schema.json`; семантические проверки реализованы в `ddh_memory.py`. Значение `schema_version` — `ddh-memory-event/1`. `--raw` дополняет `raw_refs` хешем и размером файла перед записью. Повторный вызов с тем же `event_id` и содержимым идемпотентен; с другим содержимым завершается конфликтом. Не генерировать новый `event_id` при повторе одного и того же источника.

`basis` отделяет `observed`, `derived` и `synthetic`. Это заявления поставщика входов; проверка хеша не доказывает истинность текста, независимость оценщика или наличие всех разговоров. Синтетические фикстуры не могут поддерживать реальные факты и не участвуют в извлечении навыков.

`coverage.status`:

- `captured_sources_only` — доступны только явно переданные источники; это не заявление о полноте дня.
- `partial` — известны пропуски, перечисленные в `limitations`.
- `unknown` — покрытие неизвестно, с объяснением причины.

Ссылка сама по себе не архив. Для `source` нужны сохранённые байты. Если полный разговор недоступен, сохранить доступный фрагмент с указанием границ; не называть реконструкцию точной стенограммой.

## Дневная консолидация и блог

`daily` вычисляет окно `[21:00 предыдущего дня, 21:00 выбранного дня)` в **явно переданном** часовом поясе. Порог можно изменить через `--cutoff`. Отбор по `captured_at` включает поздно поступившие сведения; отдельный `late_arrivals` содержит записи, произошедшие раньше окна. Так записи после вечернего выпуска переходят в следующий, а не исчезают между календарными сутками. Не известные модулю события он восстановить не может.

Выход команды — план синтеза, а не готовая статья. Вызывающий адаптер отдельно:

1. Архивирует доступные исходники и результаты; выполняет `verify`.
2. Формирует частный дневной обзор с источниками, решениями, открытыми вопросами, поправками и ограничениями покрытия.
3. Создаёт публичную редакцию только из разрешённых к публикации утверждений. Не копирует внутренний контекст, финансовые или кадровые данные по одному признаку «сделано за день».
4. Формирует предложения изменений кейсов с конкретными source IDs и diff; непроверенные результаты не становятся достижениями.
5. Публикует через реально доступный сайт-адаптер и сохраняет URL/ревизию/результат. Недоступная публикация остаётся `blocked`, без выдуманного URL.

Сам модуль запрещает повышение видимости источника в обычном событии. Разрешённая пользователем публикация выполняется отдельной редакционной проекцией с собственным явным договором видимости. Это ограничение данных не требует заново спрашивать уже данное разрешение на публикацию подходящего материала.

## Жизненный цикл навыков

`workflow_result` фиксирует `key`, стабильный `run_id`, `context_key`, результат приёмки, способ проверки и будущего канонического владельца процедуры. Реальный результат не равен самооценке агента.

В первой версии правило предложения — не менее трёх различных успешных запусков в двух контекстах. Это **настраиваемое инженерное стартовое правило**, не научно доказанный порог. `--min-successes` и `--min-contexts` изменяют его. Считаются уникальные запуски; дубликаты эмиссий не накапливают успехи. Противоречивые отчёты одного запуска исключаются и показываются отдельно. `fail`, `blocked`, `unknown`, `self_report` и синтетические данные не являются положительным подтверждением.

Если в реестре уже есть соответствующий навык, предлагается `review_existing`, иначе `author_candidate`. Выход сохраняет ссылки на свидетельства и условия приёмки. Он не выдаёт автоматически сочинённую процедуру за проверенную и не устанавливает `SKILL.md` в активные каталоги. Семантическое обнаружение новых классов задач, авторинг кандидата, проверка пересечения с другими навыками и его применение — следующий адаптер. Сейчас группировка использует явные `workflow.key`.

Целевой цикл:

`наблюдение → кандидат → проверка формата/источников → одинаковые задачи с навыком и без → проверка триггеров и переносимости → принятый навык → наблюдение за дрейфом`.

Условие принятия — полезное поведение на отложенных сценариях, а не просто повторение процесса. Доля успешных запусков, критические ошибки, ложные активации, стоимость, задержка, человеческие исправления и конфликтность инструкций учитываются раздельно. Не задавать произвольную общую оценку, способную скрыть ухудшение точности.

Новая модель не делает все прежние навыки ненужными. Часть хранит знания проекта, права, источник данных или требуемую методику; она остаётся необходимой даже при лучшем рассуждении. Процедурную опору можно сокращать, когда сравнение показывает отсутствие полезного эффекта и сохранение всех обязательных условий.

## Обновление модели и среды

`contracts/environment-fingerprint.schema.json` требует наблюдаемые поля и источник наблюдения. Неизвестное значение — `null`. Сравниваются provider, model ID/revision, host/version, digest набора инструментов, политика контекста и каталог навыков.

- Изменение двух известных значений даёт `observed_configuration_change` и предложения `revalidate` для активных навыков.
- Впервые открывшаяся revision — `newly_observable_dimensions`, а не доказанное обновление модели.
- Изменение только хоста не называется обновлением модели.
- Стабильный alias без открытой revision не позволяет обнаружить скрытую замену модели у провайдера. `hidden_provider_rollout_detection: unsupported` сохраняется явно.
- Команда не является постоянно работающим watcher. Её следует вызывать адаптером на старте сессии, при наблюдаемом событии смены модели и в плановой диагностике.

В `0.1.0` автоматические предложения после смены конфигурации означают **перепроверить**, а не заранее придуманные «удалить/изменить». Вывод об изменении, объединении или удалении конкретного навыка появится из сравнительных прогонов. Удаление активных навыков модуль не выполняет.

## Надёжность и границы

Локальный writer использует эксклюзивный каталог блокировки, запись временного файла, `fsync`, затем атомарную замену. Сначала записываются исходные объекты, затем ссылающаяся запись. Прерванный запуск может оставить лишний непривязанный объект; `verify` сообщает о нём, но не удаляет автоматически. Старая блокировка после аварии требует проверки оператора; программа не снимает её по возрасту.

Это защита от штатных конфликтов и случайной порчи, не криптографическая аутентификация автора. Изменяющий все файлы и хеши процесс способен изменить архив; для долговременного владения нужны история Git, независимая резервная копия и права доступа. Не использовать общий каталог сетевого диска как распределённую базу. Для нескольких устройств нужен Git/сервис с условной записью по revision и разрешением конфликтов. Этот модуль не синхронизирует устройства самостоятельно.

Из-за полного чтения/проверки журнала прототип рассчитан на небольшой локальный корпус. Для большого корпуса нужен восстанавливаемый индекс SQLite/поисковый сервис. Поиск сейчас лексический; его полнота не измерена. Семантические embeddings не нужны для сохранности исходников и не заменяют их.

Модуль не получает скрытые системные сообщения, внутренние рассуждения модели или гарантированный pre-compaction hook. Сохранность возможна для доступных и действительно захваченных материалов. Утверждать «ни одной потери во всех средах» до измерения capture coverage и испытания восстановления нельзя.

## Проверка

```bash
python3 -m unittest discover -s modules/continuous-memory/tests -v
```

Тесты используют только временные синтетические данные. Проверяются точность байтов, идемпотентность, отказы при конфликте/порче/отсутствии исходника, сохранение исправленной истории, запрет подмены фактов саммари, приватность, циклы, дневная граница/поздние поступления, повторные запуски и неизвестные версии моделей. Это не проверка live Codex/DSH/Kimi, не испытание семантического качества и не доказательство надёжности сайта/планировщика.

## Первичные основания

- [Agent Skills specification](https://agentskills.io/specification): переносимый формат metadata/instructions/resources; хост всё равно должен обнаружить и корректно применить навык.
- [Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills): реалистичные сценарии, базовая линия без навыка, итерации на основании результатов.
- [SkillsBench, v4](https://arxiv.org/abs/2602.12670v4): парные измерения на одинаковых задачах и существенная зависимость эффекта от конфигурации; опубликованные результаты не являются результатами этого DDH.
- [Voyager](https://github.com/MineDojo/Voyager): практическая демонстрация накопления повторно используемых процедур по обратной связи в Minecraft. Используем идею, а не переносим игровой runtime или обещания его результатов на рабочие задачи.
- [NVIDIA SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator): отдельные уровни проверки формата/совместимости, пересечения навыков и реального влияния. Кандидат для следующего этапа CI; не установлен этим модулем.

Этот модуль написан отдельно; код перечисленных проектов не скопирован. Лицензия DDH не назначается этой поставкой автоматически.

## Пакет для новой сессии

`context_pack.py` собирает ограниченный приватный пакет из выбранных закреплённых источников, проверяет точные байты и выдаёт адреса отложенных документов. Поддерживаются локальные Git-объекты и явно переданные экспорты с pins; подробнее — [README.context-pack.md](README.context-pack.md). Он не создаёт второй журнал задач DDH/CPT, не подключает host hooks и не переносит скрытый контекст. Версия инструмента пакета — `0.1.0`; формат памяти и версия ядра остаются прежними.
